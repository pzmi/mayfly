# 0018. Event codec and aggregate registry

Date: 2026-11-09

## Status

Proposed; amended 2026-11-09.

## Context

Plan §5.3 and fnd §6.1 ask for versioned events registered in one registry, each with a golden
JSON fixture, read through pure upcasters; ver §3.1 asks every aggregate module for accepted and
refused `DETERMINISM_CASES`, and for the set of modules with cases to equal the set of
aggregates. `mayfly-control-domain` is pure (fnd §2.3): it may derive `serde` but must not name
a format such as `serde_json`. The journal adapter stores the kind (`type`, `schema_version`)
and the payload in separate columns. KER-04..06 add aggregates and must not have to touch the
harnesses to be covered.

Alternatives considered: a global, string-keyed table of decode function pointers (a pointer
cannot be generic over a `Deserializer`, so it would force a format into the pure crate or an
erased-serde dependency); a `#[serde(tag = "type")]` enum (puts the kind inside the payload,
cannot carry a version, and duplicates the journal's columns); a `const DETERMINISM_CASES` slice
(events and commands are not `const`-constructible).

## Decision

- Each event struct implements `DomainEvent` (`EVENT_TYPE`, `SCHEMA_VERSION`). An aggregate's
  events form one enum declared with `event_set!`, which implements `EventSet`: the current and
  legacy kinds as constants, `kind()`, and `encode`/`decode` written against serde's
  `Serializer`/`Deserializer` traits. The payload is the struct's own serde form; the kind
  travels beside it. An unknown kind decodes to `DecodeError::UnknownKind` (safe mode), never a
  guess.
- The upcaster hook is the macro's `legacy { Old => fn(Old) -> Enum }` block: legacy versions
  are decoded and upcast on load, never written.
- `Aggregate` (`NAME`, `State`, `Body`, `Event`, `Rejection`, `initial`, `decide`, `evolve`) with
  the caller-supplied `Command { command_id, issued_at, body }` envelope; `Rejection` is a trait
  each aggregate's refusal type implements with a stable `code()`.
- Cases are `DeterminismCases::determinism_cases()`. An `AggregateRegistry` is walked by an
  `AggregateVisitor` whose `visit::<A>()` requires `A: DeterminismCases`, so a registered
  aggregate without cases does not compile. `ControlAggregates` is the one registry: its
  aggregates' event sets are the event registry.
- The golden and determinism harnesses live in `mayfly-testkit` (test-only, `serde_json`) and
  walk any registry. A fixture is the payload as pretty JSON with a trailing newline,
  `<type>/v<n>.json`; a legacy kind adds `v<n>.expected.json`, its upcast current encoding.

## Consequences

An aggregate plugs in with one `visitor.visit::<A>()` line and is then covered by both
harnesses and by `known_kinds`. The pure crate names no format; ES-01/ES-02 decode journal rows
through `EventSet::decode` with their own `serde_json` deserializer. An `Aggregate` impl left
out of the registry is not caught at run time (its events would have no fixtures, and an
existing fixture would be reported unregistered); an architecture rule that every
`impl Aggregate` appears in `ControlAggregates` is needed for that, along with the hash lock
of frozen fixtures (`fixtures.lock`, ES-03R). Reversal means a new ADR.

## Amendment (2026-11-09): sample coverage, upcast kind, determinism comparisons

Review of the first harnesses (KER-03F) found that one frozen sample per kind let an optional
(`skip_serializing_if`) field or an unsampled nested variant be renamed without breaking any
fixture; that an upcaster landing on the wrong event type passed; and that the determinism
harness trusted `PartialEq` alone, which a hand-written impl can make blind to a field.

- **Samples.** A kind may have extra samples `<type>/v<n>.<slug>.json` (`<slug>` is
  `[a-z0-9][a-z0-9-]*`) beside the primary `v<n>.json`; a legacy kind has a
  `v<n>[.<slug>].expected.json` beside each. Every sample decodes, round-trips (current) or
  upcasts exactly (legacy), and folds through `evolve(initial(), event)` without a panic.
- **Coverage, by tracing.** `EventSet::shape(kind)`, generated by `event_set!`, traces the
  payload type's own `Deserialize` impl (`mayfly_control_domain::shape`, pure, no format) into
  every struct field and enum variant it can hold. The harness reads the samples' JSON against
  those paths and fails (`Uncovered`) on any field or variant no sample shows, so each one is
  in a frozen file and a rename breaks it. Tracing was chosen over a list each event declares:
  a hand-kept list can leave out exactly the field nobody sampled, and nothing could check it.
  A payload that needs a self-describing format (internally, adjacently or untagged enums,
  `flatten`), or a part nothing can reach (behind a tuple element or map key that refuses a
  made-up value), fails as `Untraceable` instead of passing unchecked: events use structs,
  externally tagged enums, `Option`, `Vec` and string-keyed maps.
- **Upcast kind.** An upcast must produce the current version of the legacy kind's own type
  (`KindMismatch`); the old current-fixture kind check, which could not fail, is gone.
- **Determinism.** Two decides (and two folds) must agree by `PartialEq`, by `Debug`, by each
  event's encoded bytes and by `Rejection::code()`. Each aggregate needs a case with a
  non-empty history. `Rejection` gains `const CODES`, every code a refusal can carry; a case
  refused with an unlisted code fails.
- **Decisions golden.** `determinism::verify` takes a directory and compares each aggregate's
  codes and case outcomes with `<aggregate>.txt` there
  (`crates/mayfly-control-domain/tests/fixtures/decisions/`). It catches an outcome that changes
  between builds or processes, which two calls in one process cannot, and shows a renamed code
  in review. Unlike event fixtures it may be regenerated, deliberately (ver §4.2): a missing or
  different golden fails with the text to commit.

Consequences: an event type's author commits one sample per optional field and variant (the
failure names each missing one) and an aggregate's author commits its decisions golden. The
tracer lives in the pure crate because only it may name `serde` (fnd §2.4); it uses no format.

## Amendment (2026-11-09): what the tracer can see, and where it lives

Review of the sample-coverage amendment (KER-03G) found four ways the shape tracer passed a
payload it had not fully seen: recursion was detected by serde container name alone, so a
generic `Change<T>` nested as `Change<Limits>` holding `Change<Mode>` (or two types both named
`Detail`) silently lost the inner one's variants; an enum carried as a string or integer
(`try_from`/`into`, `with`, `deserialize_with`) traced as a plain leaf whose variants no sample
had to show; a validated id refused the tracer's made-up `""` and `0`, so an id-keyed map or an
id-first tuple was untraceable; and two different nodes at one path kept the first silently.

- **Recursion.** A container is identified by its kind, serde name, field or variant names
  (compared by content: a promoted constant can be duplicated across codegen units, so address
  identity could miss a real cycle) and the Rust type name of its visitor, which carries a
  generic type's parameters. A container that reappears inside itself is unrolled once more and
  every node of the copy must match the original at the same relative path; the third
  appearance ends the run. A copy that differs is reported (`Gap::Recursion`), and nesting past
  `MAX_DEPTH` is reported (`Gap::TooDeep`): the tracer never stops silently.
- **Leaf samples.** A leaf is offered values in turn, one per run: a string the empty string,
  then the text of each validated value type events carry, from a new pure trait
  `mayfly_domain::Sample` (pool and host names, the hex ids, `ImageDigest`, `OwnedVmName`);
  an integer its type's maximum, then 0 and 1. A refusal is caught where the leaf's visitor
  rejects the value and where the value's conversion (`try_from`) fails right after it. The
  list in `mayfly_control_domain::shape` is the allowlist of value types; the integer value
  types (`Generation`, `Epoch`, `Millis`, `Deadline`, `Slot`, `Resources`' fields) accept their
  maximum and need no entry.
- **Opaque leaves: the mechanism chosen.** A leaf that refuses every sample, or an integer that
  refuses its maximum, is reported as `Gap::OpaqueLeaf`, so the golden harness fails it as
  `Untraceable`. Rejected alternatives: a per-event declaration that the payload holds no coded
  enum (nothing could check it), and a marker trait on leaf types (serde hands the tracer a
  `String` or `u8` visitor, never the enum, so the tracer cannot see a leaf's Rust type). The
  behavioural rule is checkable and costs an author nothing unless they add a validated value
  type, which then implements `Sample` and joins the list. **Limitation:** an enum coded as an
  integer with a variant at the type's maximum, or as a string with a variant spelled exactly
  like a sample, still traces as a plain leaf. The complementary static rule (no
  `try_from`/`into`/`with` on an event payload's enums) belongs to the architecture checker and
  is not part of this amendment. *(It landed as `ARCH-event-payload-serde`: see the ARCH-04
  amendment below.)*
- **Gaps.** `Shape::untraceable` maps each path to its `Gap` (self-describing format, unreached,
  opaque leaf, conflict, recursion, too deep, not converged); two different nodes at one path
  (a tuple's elements share `[]`) are a `Conflict`, not first-wins.
- **Aliases.** serde lists a `#[serde(alias)]` name among a struct's fields and an enum's
  variants, and the tracer cannot tell it from the primary name, so it is an item a sample must
  show, and a sample that shows it re-encodes under the primary name and fails byte identity:
  aliases are refused in event payloads, consistent with "a rename is a new version".
- **Harness.** A registered kind whose `EventSet::shape` is `None` fails (`NoShape`) instead of
  skipping coverage. Every code in `Rejection::CODES` must be returned by some refused
  determinism case (`UncoveredCode`), so each code's outcome is pinned in the decisions golden.
- **Registration.** An `impl Aggregate` left out of `ControlAggregates` is refused by the
  architecture rule `ARCH-aggregate-registered` (ARCH-01), as the consequences above asked;
  `fixtures.lock` remains planned (ES-03R).

**Why the tracer lives in the pure crate.** Only `event_set!` knows which payload type each
`(type, version)` kind decodes to, and it expands in the crate that declares the events, so the
shape must be reachable from `EventSet` there; the tracer itself names no format, so it may sit
beside the codec (fnd §2.3, §2.4). The alternative was a `visit_payload::<V>(kind, visitor)`
hook on `EventSet` that hands the payload type to a visitor generic over `DeserializeOwned`,
with the tracer in the test kit; it keeps the pure crate smaller but adds a second generic entry
point every event set must carry and splits the shape rules from the codec they describe. It
remains open if the pure crate's tracer grows.

## Amended 2026-11-09 (planner): the static rules behind the tracer (ARCH-04)

Review of the tracer amendment (KER-03G) left three things to the architecture checker and one
to a test; ARCH-04 lands them.

- **A catch-all coded enum.** Besides the limitation above, an enum coded as a string or integer
  whose conversion accepts *any* value (an `Other(String)` fallback) accepts the tracer's first
  sample, so it traces as a plain leaf and is not even reported as opaque; likewise a
  `#[serde(other)]` variant decodes every unknown variant name, so a renamed variant would load
  as the catch-all instead of failing. The tracer cannot see either, by design: serde hands it a
  `String` or `u8` visitor, and an unknown name never reaches it. The architecture rule
  `ARCH-event-payload-serde` prevents both statically: production code of
  `mayfly-control-domain`, which declares the events, writes no `#[serde(..)]` with `try_from`,
  `from`, `into`, `with`, `deserialize_with`, `serialize_with`, `alias`, `other`, `untagged`,
  `tag`, `content` or `flatten` (container, field or variant, through `cfg_attr` and in macro
  tokens; arguments that do not parse are refused too) and no hand-written `Serialize` or
  `Deserialize` impl. The rule covers every type of the crate rather than the types an
  `event_set!` reaches: a reachability analysis by name could miss exactly the type that matters,
  and the crate holds only events, the types they carry and the kernel. `mayfly-domain`, whose
  value types events carry, is held to the same rule except that a struct there may convert
  (`try_from`, `from`, `into`): its validated value types decode through their parsers on
  purpose and are the stated exception; an enum there may not convert. The edge table lets
  `mayfly-control-domain` depend on `mayfly-domain` alone (fnd §2.2), so the two crates hold
  every workspace type an event can carry; a new edge adds its crate to the rule's list.
- **Validated types stay on the list.** `ARCH-sample-coverage`: every `mayfly-domain` type
  decoded through a container `try_from` from anything but an integer implements `Sample` and
  is listed in `texts()` of `shape.rs`; a type a `macro_rules!` declares (`hex_id!(EventId)`) is
  resolved through the macro's trailing `$name:ident` and its invocations, and one that cannot be
  resolved is reported. Integer-coded types (`Generation`) need neither, as above.
- **Event sets come from the macro.** `ARCH-event-set-macro`: production code implements
  `EventSet` only inside `macro_rules! event_set` in `src/event.rs`, so every set has the
  generated `shape()`; the harness's `NoShape` failure stays the run-time backstop, and test code
  may still write a set by hand to exercise it.
- **Field and variant names in a container's identity** are kept and pinned by
  `should_trace_both_when_a_nested_container_differs_only_in_its_field_names`: a container that
  holds another with the same serde name, length and visitor type but different field names (a
  hand-written visitor choosing its field list by depth) is another type, and without the names
  the tracer would report the inner one as a differing recursive copy instead of tracing it.

## Amended 2026-11-09 (ES-03, proposed): command bodies, refusals and epochs

ADR 0041 adds to the aggregate contract: `Aggregate::Body` implements `CommandBody` (a
`snake_case` `command_type`, its `TYPES` and `Serialize`, the canonical form of the intent
digest); `Rejection` serialises and deserialises (a refusal receipt replays it);
`Aggregate::SUPPORTED_EPOCH` and `DomainEvent::REQUIRED_EPOCH` (default 1) with
`EventSet::required_epoch` generated by `event_set!` (`doc/event-store.md` §6.2). The
determinism harness checks command types as it checks refusal codes, and the golden harness fails
a sample needing more than its aggregate supports.
